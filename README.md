# Taskbar Audio Spectrum

[![Build and test](https://github.com/ShangHTao/TaskbarAudioSpectrum/actions/workflows/build.yml/badge.svg)](https://github.com/ShangHTao/TaskbarAudioSpectrum/actions/workflows/build.yml)
[![Release](https://img.shields.io/github/v/release/ShangHTao/TaskbarAudioSpectrum)](https://github.com/ShangHTao/TaskbarAudioSpectrum/releases/latest)
[![License](https://img.shields.io/github/license/ShangHTao/TaskbarAudioSpectrum)](LICENSE)

Taskbar Audio Spectrum turns the native Windows taskbar search box into a
real-time system-audio visualizer. It captures the playback mix through WASAPI
loopback and draws a lightweight, click-through spectrum while preserving the
normal behavior of the search box.

![Taskbar Audio Spectrum running in the Windows taskbar search box](assets/taskbar-spectrum-preview.png)

## Features

- Native Windows 10 and Windows 11 taskbar integration
- Portable standalone application and generated Windhawk mod source
- WASAPI loopback capture with automatic default-device reconnection
- 4,096, 8,192, and 16,384-point FFT analysis
- Third-octave, Bark, logarithmic, Mel, and linear frequency layouts
- Peak, energy, mean, and Slaney band aggregation
- Hann, Hamming, and Blackman-Harris windows
- Optional A/C frequency weighting, peak markers, and silence hiding
- Per-monitor DPI scaling and recovery after Explorer or Search restarts
- Strict UTF-8 JSON configuration with actionable validation errors
- No microphone access and no third-party runtime dependencies

## Requirements

- Windows 10 or Windows 11 on an x64 PC
- Taskbar **Search** set to the full **Search box**
- An active Windows playback device

The spectrum represents relative digital playback power. It is not a
calibrated sound-level meter and does not report dB SPL, dBA, Class 1, or
Class 2 measurements.

## Install the standalone application

1. Download `TaskbarAudioSpectrum-v1.0.0-win64.zip` from the
   [latest release](https://github.com/ShangHTao/TaskbarAudioSpectrum/releases/latest).
2. Extract the archive to a permanent writable directory.
3. Run `TaskbarAudioSpectrum.exe`.

The included `spectrum.json` is the recommended default profile. The
application can also run with built-in defaults when the file is absent.
Starting a second copy replaces the running instance and reloads the
configuration.

To stop the application without starting a replacement:

```powershell
TaskbarAudioSpectrum.exe --exit
```

Set `startup.startWithWindows` to `true` in `spectrum.json` to launch the
standalone application when you sign in. Move the application first, then run
it once from its final location so the startup entry records the correct path.

## Install with Windhawk

The release includes `taskbar-audio-spectrum.wh.cpp`, the complete source file
generated by CMake for Windhawk. It is source code, not a prebuilt DLL:

1. Download the `.wh.cpp` file from the latest release.
2. In Windhawk, choose **Create a new mod**.
3. Replace the editor contents with the downloaded source, then compile and
   enable the mod.

The mod runs the shared runtime in a dedicated `windhawk.exe` tool process and
exposes its settings in Windhawk. Do not run the standalone application and
the Windhawk mod at the same time, because both would render the same overlay.

## Configuration

Edit `spectrum.json` beside the standalone executable, then restart the
application. JSON must be UTF-8 and use the documented value types. Comments,
unknown fields, obsolete fields, and incorrectly typed values stop startup;
the reason is written to `spectrum.log` without modifying the file.

The default profile uses 28 nominal one-third-octave bands, a 16,384-point Hann
FFT, 75% overlap, energy aggregation, and a 30 FPS display. Start with
[spectrum.example.json](spectrum.example.json), then use the complete
[configuration reference](docs/Configuration.md) for every setting and range.

## Build and test

Install Visual Studio 2022 with the **Desktop development with C++** workload
and CMake 3.25 or newer. The included [.vsconfig](.vsconfig) lists the required
Visual Studio components.

```powershell
git clone https://github.com/ShangHTao/TaskbarAudioSpectrum.git
cd TaskbarAudioSpectrum
cmake --preset windows-debug
cmake --build --preset windows-debug
ctest --preset windows-debug
```

Create an optimized standalone build and ZIP package with:

```powershell
cmake --preset windows-release
cmake --build --preset windows-release
ctest --preset windows-release
cpack --config build/windows-release/CPackConfig.cmake -C Release
```

Visual Studio presets place executables inside the selected configuration
directory, for example
`build/windows-release/Release/TaskbarAudioSpectrum.exe`.

The generated Windhawk source is produced by the CMake target and is never
stored in the repository:

```powershell
cmake --build build/windows-release --config Release --target tas_windhawk_source
```

Compiling the generated source for both Windhawk architectures uses the
Ninja-based `windows-ci` preset and a Windhawk compiler installation. See the
[development guide](docs/Development.md) for the full toolchain instructions.

## Project structure

```text
include/taskbar_audio_spectrum/  Shared project contracts
src/                            Runtime and standalone implementation
src/windhawk/                   Windhawk metadata, adapter, and launcher
tests/                          Deterministic automated tests
diagnostics/                    Interactive Windows diagnostics
cmake/                          Windhawk source generation
```

Private implementation headers belong under `src/`; `include/` contains the
contracts shared by build targets. The generated
`taskbar-audio-spectrum.wh.cpp` exists only under `build/` and in release
assets.
